# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

MeshCore-BTC is a general-purpose bot framework for a MeshCore LoRa mesh device connected over USB serial. The
framework (`core/`) handles the connection, message dispatch and rate-limited sending; actual behavior lives in
independent modules (`modules/`). Two ship today:

- **`bitcoin`** - broadcasts a daily Bitcoin price update to a channel, with trend emoji, optional Fear & Greed
  Index (`api.alternative.me`), optional network hashrate (`blockchain.info`), and optional Aave EURC/USDC borrow
  rates (via an Ethereum RPC, `ethers`). Price source: `api.coingecko.com`.
- **`ai`** - answers direct messages (always) and channel messages (per-channel `"mention"`/`"all"` mode) using a
  locally-running Ollama model.

See `README.md` for full details (config reference, AI semantics, module authoring guide) and `DEPLOYMENT.md` for
host deployment steps.

## Commands

```bash
npm install
node index.mjs                # uses "port" from config.json
node index.mjs /dev/ttyACM0   # override the serial port
./run.sh                      # auto-restart supervisor - use this in production
```

**Requirements:** Node.js 22+ (LTS), MeshCore device with Companion USB firmware; Ollama running locally (with the
configured model pulled) if the `ai` module is enabled.

## Architecture

```
index.mjs                  Thin bootstrap: loads config, builds the module list, calls startBot()
core/framework.mjs         startBot(config, modules) - connection lifecycle, normalization, dispatch, ctx factory
core/send-queue.mjs        SendQueue - global FIFO send queue with min-gap rate limiting (sendIntervalSeconds)
core/watchdog.mjs          startWatchdog() - activity watchdog, exit(42) on a hung connection
modules/bitcoin.mjs        Daily price broadcaster (moved from the old monolithic index.mjs)
modules/ai.mjs             Ollama-backed responder
utils.mjs                  Shared helpers: formatPrice/formatHashrate/formatBorrowRate, shortenToBytes,
                            splitToBytes, loadJson/saveJson, fetchWithRetry, sleep, setAlarm
run.sh                     Supervisor loop - restarts index.mjs whenever it exits (crash or watchdog)
config.json                Local configuration (gitignored - copy from config.json-example)
price-history.json         Auto-generated by modules/bitcoin.mjs, stores last price for trend comparison
```

**Module contract** - each file in `modules/` default-exports:

```js
{ name, init(ctx)?, onChannelMessage(msg, ctx)?, onDirectMessage(msg, ctx)? }
```

`ctx` (one instance per module) provides: `config`, `moduleConfig` (`config[name]`), `self` (`{name, publicKey}`),
`limits` (`{channelMessageBytes, directMessageBytes}`), `log`/`logError`, `utils`, `getChannelByName`/
`getChannelByIdx`, `sendToChannel(channelIdx, text)`/`sendToContact(publicKey, text)` (byte-truncated, queued,
resolve after actual transmission), `registerAlarm(timeHHMM, cb)`, and the raw `connection` escape hatch. A module
throwing from `init()` is logged and disabled (removed from dispatch) without crashing the bot; hook errors are
caught per-module per-message.

Normalized messages passed to hooks: `{kind:'channel', channel:{channelIdx,name}, text, senderName, body, fromSelf,
raw}` and `{kind:'direct', contact, senderName, pubKeyPrefix, text, raw}`. Channel sender-name parsing assumes a
`"SenderName: message"` text prefix (unverified library behavior) - parsed defensively via regex, raw messages are
always logged at debug level.

**Send queue:** all outgoing messages, from every module, funnel through one `SendQueue` (`core/send-queue.mjs`)
that paces transmissions at least `sendIntervalSeconds` (default 15s) apart, FIFO, capped at 20 queued jobs.

**Watchdog / Auto-Restart:** `core/watchdog.mjs` listens on `connection.on('rx', ...)` and `connection.on('connected',
...)` (not a monkey-patched `emit`) to track the last time the device produced real activity. A 60-second timer
checks the idle time; once it exceeds `config.watchdogTimeoutMinutes` (default 360 = 6h), it logs a `WATCHDOG:`
message and calls `process.exit(42)`.

Exit code `42` has no special meaning to Node itself — it's just how the bot communicates "I gave up, please
restart me" to whatever is supervising it. `run.sh` is that supervisor: it loops forever, restarting `node
index.mjs` after any exit (watchdog-triggered or otherwise) with a 10s delay, logging the exit code and timestamp
each time. Run the bot via `./run.sh` in production instead of calling `node index.mjs` directly.

## Configuration

```json
{
  "port": "/dev/ttyACM0",
  "transport": { "type": "serial" },
  "watchdogTimeoutMinutes": 360,
  "sendIntervalSeconds": 15,
  "limits": { "channelMessageBytes": 155, "directMessageBytes": 160 },
  "modules": { "bitcoin": true, "ai": true },
  "bitcoin": {
    "channel": "Public",
    "alarm": "6:00",
    "priceFile": "./price-history.json",
    "showFearGreed": true,
    "showHashrate": true,
    "showBorrowRates": true
  },
  "ethereum": { "rpcUrls": ["..."], "aavePoolAddress": "0x..." },
  "ai": {
    "ollamaUrl": "http://localhost:11434",
    "model": "gemma4:12b-mlx",
    "requestTimeoutSeconds": 120,
    "historyLength": 6,
    "maxParts": 3,
    "channels": { "Public": "mention" },
    "systemPromptExtra": ""
  }
}
```

Legacy top-level keys `bitcoinAlarm` and `channels.bitcoin` still work as fallbacks in `modules/bitcoin.mjs`. See
`README.md` for the full annotated config reference.
